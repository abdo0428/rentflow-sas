# Authorization

## الأدوار

| الدور | الصلاحيات |
| --- | --- |
| super_admin | جميع الصلاحيات وجميع الشركات |
| company_admin | جميع عمليات شركته والتقارير والإعدادات، دون إدارة الشركات |
| property_manager | المباني والوحدات والمستأجرون والعقود والصيانة وتكليفها والإعلانات والمستندات والتقارير؛ قراءة الدفعات |
| accountant | قراءة العقارات والمستأجرين والعقود؛ قراءة/إنشاء/تحديث الدفعات؛ قراءة/إنشاء المستندات والتقارير |
| maintenance_staff | قراءة وتحديث طلبات الصيانة المسندة إليه فقط؛ لا يكلّف الطلبات |
| tenant | قراءة وحداته وعقوده ودفعاته ومستنداته والإعلانات ذات الصلة؛ قراءة وإنشاء طلبات صيانته |

الصلاحيات تستخدم `resource.action` مثل `payments.view` و`maintenance.assign`. تعريفها الكامل في RolePermissionSeeder. صلاحيات التعديل جاهزة للمراحل اللاحقة ولا تعني وجود مسارات CRUD في المرحلة الأولى.

## طبقات الحماية

1. المسارات: auth + active + verified + permission؛ الملف الشخصي متاح قبل تحقق البريد لتصحيحه.
2. Controllers: تستدعي policy للسجلات وGate للتقارير والإعدادات.
3. Policies لكل موديل تعيد فحص الإذن والشركة وظهور السجل للمستخدم المعني.
4. CompanyScope عالمي على موديلات المجال بما فيها الشركات وسجلات التدقيق؛ الزائر والمستخدم غير النشط بلا نتائج، والشركة الموقوفة محجوبة.
5. tenant مقيد بعلاقة user_id، ثم tenant_id والوحدات المؤجرة له. الإعلان يجب أن يكون منشورًا، حل موعده وموجهًا لشركته أو مبناه. الصيانة مقيدة بـ assigned_to للموظف، وبقية سجلات المجال محجوبة عنه.
6. BelongsToCompany يستنتج الشركة من المستخدم عند الإنشاء، ويرفض نقل السجلات بين الشركات. المفاتيح المركبة تحمي الاتساق في MySQL.
7. التنزيل يمر بالمصادقة والصلاحية وscope وpolicy؛ لا تُعرض مسارات الملفات الخاصة.

User لا يطبق global scope لتجنب تعطيل تحميل هوية المستخدم عند تسجيل الدخول. لا توجد صفحة دليل مستخدمين أو API عام؛ حسابه يُقرأ ويُحدّث عبر المستخدم المسجل فقط. عند إضافة إدارة الموظفين يجب تقييد استعلام User بالشركة.

## سياق الأعمال الخلفية

القراءة دون هوية تفشل مغلقة، حتى في console. استخدم `app(Tenancy::class)->runFor($user, fn () => ...)` للعمل المقيد بهوية. `runWithoutScope` مخصص لعمليات موثوقة مثل seed وتهيئة شركة جديدة، ويستعيد السياق عبر finally. لا تقبل مفتاح التجاوز أو company_id من المستخدم. إنشاء fixtures في console مسموح؛ تمر طلبات الويب بسياسات وForm Requests.

لا تستخدم DB::table أو withoutGlobalScopes أو bulk update/delete لبيانات الأعمال في مسار المستخدم: تتجاوز scopes أو أحداث الموديل. تحقق من الصلاحية قبل الكتابة ومن العلاقات المحددة عبر المستخدم. السياسات ليست بديلًا عن قصر الحقول القابلة للتعديل في Form Requests، خصوصًا assigned_to والحالة في دورة الصيانة القادمة.

التسجيل العام يحدد company_admin داخل معاملة، ولا يثق بحقول role/company_id/status المرسلة. منع الدخول يشمل المستخدم غير النشط والشركة الموقوفة. الحسابات المرتبطة بسجلات أو مدير الشركة الوحيد لا تحذف نفسها.
