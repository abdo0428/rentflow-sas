# سيناريوهات استخدام RentFlow

للعرض التجريبي استخدم حسابات README وكلمة المرور `password`. سجّل الخروج قبل تبديل الأدوار.

1. **إضافة مبنى ووحدات للشركة:** سجّل الدخول بحساب `admin@example.com`، ثم Buildings → Create. أضف وحدات من صفحة المبنى أو Units، واختر البناء ورقم الوحدة والطابق والإيجار. رقم الوحدة فريد داخل المبنى.
2. **إضافة Tenant:** من Tenants أنشئ سجلًا بالاسم والبريد والهاتف. صفحة التفاصيل تجمع العقود والدفعات والصيانة والوثائق المرتبطة. إنشاء سجل مستأجر لا ينشئ حساب دخول تلقائيًا؛ حساب المستأجر التجريبي مرتبط مسبقًا.
3. **إنشاء Lease:** اختر مستأجرًا ووحدة vacant/reserved، ثم المدة والإيجار والتأمين ويوم الاستحقاق. يمكن حفظ draft ثم تفعيله. العقد النشط المتداخل يُرفض.
4. **توليد Payments:** التفعيل يولّد تلقائيًا دفعة لكل شهر ضمن المدة ويحوّل الوحدة إلى occupied. يوم 31 يُعدّل إلى آخر يوم صالح في الأشهر الأقصر. راجع الجدول في تفاصيل العقد.
5. **تسجيل Payment:** افتح دفعة pending/overdue بحساب المدير أو `accountant@example.com`، وحدد وقت السداد والطريقة وأكّد العملية. تصبح paid ويظهر تنزيل الإيصال، مع إشعار لصاحب حساب المستأجر.
6. **فتح Maintenance Request:** بحساب `tenant@example.com` افتح Maintenance → Create، واختر الوحدة الحالية وأدخل العنوان والوصف والأولوية والموعد المفضل. الصورة اختيارية وخاصة.
7. **تعيين Maintenance Staff:** بحساب المدير، انقل الطلب new إلى under_review، ثم عيّنه لموظف صيانة نشط في الشركة. يصل إشعار للموظف.
8. **إغلاق الطلب:** بحساب `maintenance@example.com` افتح الطلب المسند، ثم انقله إلى in_progress وبعد إنجاز العمل إلى completed. يظهر التغيير في Timeline وسجل التدقيق؛ الملاحظات الداخلية لا تظهر للمستأجر. الحالات النهائية لا يعاد فتحها.
9. **استخدام Tenant Portal:** راجع الوحدة والعقد والدفعة القادمة والمتأخرات. افتح الدفعات والطلبات والإعلانات الملائمة للمبنى، ونزّل الوثائق وPDF عبر المسارات المحمية. بدّل AR/EN واختبر الهاتف. عند انقطاع الإنترنت تظهر صفحة عامة دون بيانات شخصية.

تعمل تحديثات التأخير والانتهاء عبر Scheduler. لا يمكن حذف بناء له وحدات أو مستأجر له سجل تعاقدي؛ احتفظ بالتاريخ بدل فقدانه.
